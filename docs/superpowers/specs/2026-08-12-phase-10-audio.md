# Phase 10 — Audio + CRT post-pass (design spec)

> **Finalized 2026-08-12.** Design questions resolved through brainstorming; implementation
> plan to follow via the `writing-plans` skill. No code exists yet — greenfield.

Source spec for `plan.md` Phase 10 ("Audio & juice"). Scope: procedural engine audio, tire
squeal, hybrid music/SFX playback, and the CRT post pass — all four deliverables from
`plan.md` §10, done together rather than splitting CRT into Phase 11 (an earlier draft of
this spec recommended deferring CRT; the user explicitly chose to include it now). Follows
this project's established pattern of pure/testable logic decoupled from the render/audio
edge (Hard rule 5: zero external deps in the engine core — Web Audio and WebGL2 are
browser-native APIs, so it's fine to touch them directly at the `audio/`/`ui/` edge, same
footing as `net/supabase.ts`).

---

## 1. Architecture

Two independent edge modules. Neither touches existing render/physics code paths directly;
both are read-only consumers of state that already exists.

- **`audio/SoundEngine.ts`** — owns one persistent `AudioContext` + node graph (oscillator →
  filter → gain for engine tone; noise-buffer → filter → gain for tire squeal; separate
  music/SFX buses). Polled once per rendered frame from `main.ts`'s existing
  `requestAnimationFrame` loop — not from the fixed-timestep physics loop (Hard rule 3 keeps
  that deterministic and decoupled; audio doesn't need 60Hz-exact timing). Reads
  `PlayerState` (already computed for rendering) and `ContactLatch.enter()` (already computed
  for the physics collision response, landed on `phase-9-modular-economy`). Never throws,
  never blocks construction — same discipline as `engine/loadAtlases.ts`.
- **`ui/CrtEffect.ts`** — a WebGL2 post-filter applied only at the final blit step.
  `Canvas2DBackend` keeps drawing into an **offscreen** canvas exactly as it does today —
  zero changes to `RenderBackend`, `Renderer`, or any game logic. A small compositor decides
  per frame: CRT off → copy the offscreen canvas to the visible canvas; CRT on → upload the
  offscreen canvas as a WebGL2 texture and run one fragment shader pass (scanlines, barrel
  distortion, bloom threshold/blur) before drawing to the visible canvas. Raw WebGL2, no
  PixiJS/library dependency — the shader is small enough not to need one, and this keeps
  Hard rule 5 (zero external deps) intact outside the `audio`/`net` edges. Off by default on
  mobile per the plan (viewport-width or UA check at startup).

## 2. Data flow

- `PlayerState.speed` / `.gear` → engine oscillator pitch and filter cutoff.
- `PlayerState.skidding` (boolean) + `PlayerState.skidMagnitude` (new, §3) → tire squeal gate
  and gain.
- `ContactLatch.enter()` → one-shot collision SFX trigger, reusing the exact "true on the
  first step of a new contact" signal that already prevents the physics response from
  repeating every step a bump spans.
- All reads are one-directional: audio never writes back into physics or game state.
- Render path becomes: game draws to the offscreen canvas (unchanged) → compositor either
  blits directly or runs the CRT shader → visible canvas. `main.ts` gains one new call site
  per frame; everything upstream of the offscreen canvas — projection, sprites, HUD — is
  byte-identical to today.

## 3. What already exists to drive this

`physics/Vehicle.ts` implements `PlayerState` (`types/engine.ts`) and already surfaces most
of what's needed, with one addition:

- `speed` (world u/s — HUD converts to km/h) and `gear` (`gearIdx`, live via Phase 9's
  `gearUp`/`gearDown` commands — confirm at implementation time that this is what's active,
  not the old Phase 4 stub the doc comment still references) → engine pitch.
- `skidding` (boolean) → squeal gate.
- **New:** `skidMagnitude: number` on `PlayerState`/`Vehicle`, derived from existing internal
  skid-recovery state (`recoverySteps` progress against its start value) — no new physics
  *behavior*, just surfacing a number that already implicitly exists in the recovery
  countdown. This resolves the plan's "gain by skid magnitude" requirement, which a plain
  boolean can't express. Widening `PlayerState` here follows the same precedent as Spec C's
  `braking` field: add it because the feature genuinely needs a signal nothing else provides.

## 4. Engine audio — procedural, not sampled

Signal chain per the plan: `OscillatorNode` (sawtooth) → `BiquadFilterNode` (lowpass) →
`GainNode` → SFX bus (§6).

- **Pitch:** `f_osc = f_base + (kmh / gearMaxKmh[gearIdx]) * f_range`, re-derived from
  `speed`/`gear` each polled frame. Exact `f_base`/`f_range`/high-gear base aren't specified
  anywhere upstream — ship reasonable starting constants in `constants.ts` (same pattern as
  `CENTRIFUGAL`), verify the curve moves in the right direction via a headless check, and
  flag for human ear-tuning at `npm run dev` — identical to how `CENTRIFUGAL` itself was
  tuned this session.
- **Filter:** `BiquadFilterNode` cutoff as a second function of speed/RPM (plan specifies
  "cutoff = f(RPM)" without a formula) — brightens the tone at high RPM instead of a flat
  buzz. Same "ship a default, flag for tuning" treatment as pitch.
- **One oscillator graph reused across the run**, never recreated per step (Hard rule 4 — no
  per-frame allocation — applied to the audio graph). Update existing `AudioParam`s via
  `setTargetAtTime` each poll rather than stepping `.value` directly, to avoid zipper noise.

## 5. Tire squeal — filtered noise, gated by skid magnitude

- **Source:** a pre-generated noise buffer (`AudioBuffer` filled with white noise once,
  looped via `AudioBufferSourceNode`) rather than a `ScriptProcessorNode`/`AudioWorklet` —
  simpler, no real-time synthesis needed for a short-lived cue.
- **Shaping:** high-pass `BiquadFilterNode` at ~1200Hz per the plan.
- **Gate:** `GainNode` driven by `PlayerState.skidding` (on/off) and scaled continuously by
  the new `skidMagnitude` (0..1), eased via `setTargetAtTime` to avoid clicks on transition.

## 6. Hybrid playback: streamed music, preloaded SFX

- **Music:** `<audio>` element (or `MediaElementAudioSourceNode`) for streaming — avoids
  buffering a full track into memory; matches the WKWebView-memory caution already flagged
  for Phase 11.
- **SFX:** short one-shots (collision thud, UI confirm) preloaded as `AudioBuffer`s via
  `fetch` + `decodeAudioData`, played through `AudioBufferSourceNode` instances — same
  "never block construction" discipline as `loadAtlases.ts`: kick off loads fire-and-forget,
  degrade to silence if a buffer isn't ready yet rather than throwing.
- **Bus routing:** separate `GainNode` buses for music and SFX, each feeding
  `AudioContext.destination` — lets a future settings screen offer independent volume
  sliders without touching playback code, mirroring how `net/` modules stay swappable behind
  `SaveBackend`.
- **Autoplay policy:** `AudioContext` starts `suspended` in every browser that matters here;
  `resume()` must be called from an existing user-gesture handler. Reuse one already wired in
  `main.ts` (the pointer-lock click handler, or a restart/menu keydown) rather than adding a
  new "click to start audio" prompt, unless testing shows the existing gestures fire too late
  to matter.

## 7. CRT post pass

- Scanlines + barrel distortion + bloom via a WebGL2 fragment shader (§1), off by default on
  mobile viewports, toggleable (a settings flag, persisted the same way other settings would
  be — exact toggle UI is an implementation detail, not a design constraint here).
- No changes to `RenderBackend`/`Canvas2DBackend`/`Renderer` — this sits strictly after the
  existing render path, reading its output as a texture. Keeps Hard rule 1 (segment model,
  no WebGL geometry) intact: nothing about scene geometry becomes WebGL, only a screen-space
  filter over an already-rasterized frame.
- Shader tuning constants (scanline density, distortion strength, bloom threshold) go in
  `constants.ts` alongside the audio ones, same "ship defaults, flag for human eyes" pattern.

## 8. Error handling

- No `AudioContext` support, no user gesture yet, buffer fetch failure → silence, never a
  thrown error or blocked game loop (mirrors the Supabase null-client and `loadAtlases`
  "never rejects" pattern).
- No WebGL2 support → CRT silently unavailable; the offscreen→visible blit path is already
  the default, so this degrades to exactly today's rendering with zero special-casing.

## 9. Testing (vitest)

Following the project's pattern of testing pure logic and treating browser-API edges as thin,
manually-verified wrappers (same split as `net/supabase.ts` vs. `net/leaderboard.ts`):

- **Pure and testable:** pitch/filter-cutoff formulas as standalone functions of
  `{speed, gear, gearMaxKmh}` → `{frequency, cutoff}`. `skidMagnitude` derivation as a pure
  function of `Vehicle`'s existing skid-recovery state. CRT shader *parameters* (e.g.
  mobile-default resolution) as pure functions of viewport/settings — not shader execution
  itself, which is a GPU edge.
- **Thin/manual at the edge:** `AudioContext`/node construction, `resume()` gesture wiring,
  buffer loading, WebGL2 program compilation — mirrors how `loadAtlases.ts`/
  `loadBackdrops.ts` keep the fetch-and-decode edge separate from the pure math they feed.
- **Regression guard:** the game loop completes with a stubbed/null audio backend and with
  CRT forced off, matching the existing Supabase null-client test pattern.

## 10. Done-when

Engine pitch audibly tracks speed and gear across a full gear range; tire squeal is audible
exactly while `skidding` is true, scaling with `skidMagnitude`, and silent otherwise; music
streams without blocking asset load; SFX fire with no perceptible latency; the game is fully
playable with audio blocked/unsupported (no thrown errors, no silent hang). CRT reads as a
visible scanline/curvature/bloom effect when on, is off by default on mobile, and — when
off or unsupported — the game renders pixel-identical to pre-Phase-10 output.
